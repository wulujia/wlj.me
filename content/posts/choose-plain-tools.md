我有几次换工具丢过信息，例如：

- 百度的博客关了。我没备份，写过的一些文字没了。

- 放弃 Notion。里面组织良好的一些内容导出没那么方便，干脆断舍离。

后来我选工具，有些偏执。我把工具分成三层，每层规则不一样。

一、底层：纸笔和纯文本

这层最要紧，要非常慎重，选长时间不变的东西。反而越朴素越简单，越有生命力。

我老老实实用本地文本文件 + Git 管理几乎所有东西。看起来土，但十年前的笔记今天还在，格式也没变。

按这个标准，Notion 这类我直接放弃了——所有数据结构、关联、视图，都长在它的私有体系里。我想离开时，带不走。

二、中层：稳定的大服务

邮件、云存储、网络服务、Git 托管……这些选大公司的服务。

这听起来反直觉——自己的服务器最自由，但代价是得自己运维，自己搞定安全问题，自己处理硬盘故障……规模小的时候，其实并不更稳。而 Google、GitHub、Amazon、Cloudflare……都挺稳定。

大服务负责"日常稳定"，本地文件 + Git 负责"极端情况下我还在"。

三、上层：可以随便换的工具

这一层我尽量不绑死在某个工具、某个平台上。我用各种系统：macOS、Windows、Linux、iOS、Android、鸿蒙。哪里都能跑起来的工具，往往更朴素更长久。

因为下面两层稳，上面这层我反而很灵活——Obsidian、Zed、VSCode、Cursor、NeoVim……我随时可以试可以换。它们只是看同一份文本的不同窗口，换窗口不丢东西。

当然，还得注意：保持好奇，但不盲目追新。

很多新工具一开始让人眼前一亮，用一阵子会发现：核心动作还是那几个——写下来、组织起来、找回来。多出来的功能更多是噪音，不是助力。有的工具甚至会反过来打断你的节奏，逼你去学它的概念、迁就它的设计。

新工具我会试，多看看挺好。但只有真正适合的东西，我才会留下。十年前的文本文件今天打开，还是一模一样。留在工作流里的，还是那几样朴素的东西。
