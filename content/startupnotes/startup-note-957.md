笔记 955 下，国杰评论：

> 除了将 Agent 的能力融入产品，另一个可能还需要将知识星球按 Agent 产品重新设计。

> 我说的重新设计，不是简单给知识星球增加一个 Agent 功能，也不是把首页换成聊天框、换一套 Agent 的皮肤，而是把 Agent 当成产品新的默认交互层。

> 原来是用户理解产品有哪些功能，再自己去搜索、阅读、判断和操作。按 Agent 产品设计后，可以变成用户说出想做什么，Agent 理解当前的星球、内容和权限，再调用搜索、回复、加精、标签、专栏等底层能力帮助用户完成。

> 这会带来一些变化：所有底层能力都可以被 AI 使用；搜索入口逐渐变成 AI 搜索；阅读内容时可以随时让 AI 查找相关旧帖、补充背景和辅助分析。原有页面不一定消失，它们继续承担浏览和精确操作，只是 Agent 成为串联这些能力的一层。

> 这里还有一个定位问题。如果只连接知识星球，类似现在的蘑菇 Agent，重点是把知识星球理解得足够深，最终可能成为知识星球新的交互入口。如果还连接飞书、公众号等其他平台，那就是另一个方向，更接近跨平台 Agent，知识星球只是它连接的平台之一。

> 当前蘑菇 Agent 的设计，已经在尝试第一个方向。

> 我前面提到的两个不同的产品方向。

> 一个方向是只连接知识星球，类似现在的蘑菇 Agent。它的重点是对知识星球理解得足够深，能够使用搜索、阅读、回复、加精、标签、专栏等底层能力，成为知识星球新的默认交互层。

> 另一个方向是除了知识星球，还可以连接飞书、GitHub、Figma、Linear 等外部系统。这个方向并不一定要做成 OpenCode、Codex、Claude Code 那样的通用 Agent，更准确地说，可以是“以知识星球为中心、按需连接其他工作系统的 Agent”。它要解决的是如何把成员的声音带进团队内部工作，再把产品或服务的变化带回社区。
