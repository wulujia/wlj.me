Mac 与 Linux 单机白名单 HIDS 选型

只列开源、不依赖管理服务器、能按白名单拦截程序执行的工具。目标机器是个人 Mac 和自管的 Linux 服务器。

资料截至 2026-11-15 · 范围：macOS、Linux 单机

macOS 选 Santa（North Pole Security 维护的分支）。它有 Lockdown 模式，未知程序一律不准运行，规则可以只在本机配置1,2。

Linux 选 fapolicyd。它默认信任包管理器装的文件，其他文件不准执行。RPM 系发行版最成熟，Debian 系目前是初步实现3。

两者都不管脚本：bash x.sh、python -c 只会被当成解释器本身放行。白名单旁边要再放一个行为检测工具。

一、选型对比

“单机”指不装管理服务器也能完整工作。“拦截”指程序在执行前被拒，不是事后告警。

工具系统怎么判断可信单机上手难度
SantamacOS文件哈希、签名证书、Apple Team ID是低
fapolicydLinux包管理器数据库，加手工信任列表是低（RPM 系）
TetragonLinux自己写 eBPF 策略，按程序路径匹配是中
IMA appraisalLinux内核校验文件哈希或签名是高
KubeArmorLinuxallow 策略，按进程和文件部分中

没有列入的工具：Falco、Tracee、osquery 只检测不拦截；Wazuh 要管理服务器；Objective-See 的 BlockBlock 只盯开机自启项，不是执行白名单。

二、macOS：Santa

Santa 最早由 Google 开发。Google 不再维护后，North Pole Security 接手，仓库在 northpolesec/santa，许可证 Apache-2.02。它用 Apple 的 Endpoint Security 接口在程序执行前做判断。

三种运行模式

模式遇到不认识的程序适合
Monitor放行，只记日志头一两周，用来收集白名单
Lockdown直接拦截白名单收集完以后
Standalone先挂起，用户用 Touch ID、安全密钥或密码批准后放行，并在本机自动加一条规则个人开发机

Standalone 模式适合单人使用的 Mac：遇到新程序时弹窗问一次，批准后就记住，不必事先把白名单写全1。

五种规则

规则类型匹配什么粒度
BINARY整个文件的 SHA-256最细，程序一升级就失效
CDHASH代码目录哈希，只对 Hardened Runtime 程序有效细
SIGNINGIDTeam ID 加签名标识，如 EQHXZ8M8AV:com.google.Chrome一个产品
CERTIFICATE签名叶证书的 SHA-256一张证书签的全部程序
TEAMID10 位 Apple Team ID一个开发商的全部程序

日常维护主要用 TEAMID 和 SIGNINGID，升级不用改规则。自己编译、没有签名的程序只能用 BINARY。另有 CEL 规则，可以按路径、参数、父进程等条件写表达式，但部分字段不能缓存，会拖慢执行1。

不用服务器怎么配

不接同步服务器时，规则有两个来源：配置里的 StaticRules，和命令 santactl rule2。运行模式用配置描述文件（mobileconfig）里的 ClientMode 设置。

# 允许一个开发商的全部程序（示例 Team ID 为 Google）
sudo santactl rule --allow --teamid --identifier EQHXZ8M8AV

# 允许一个本地编译的程序
sudo santactl rule --allow --path /usr/local/bin/mytool

# 查看某个程序会被怎么判
santactl fileinfo /Applications/Foo.app
待确认上面三条命令的参数按以往版本写成，没有在当前版本上运行。使用前用 santactl rule --help 核对一次。

管不到的地方

官方文档写明，管理脚本执行“目前无法实现”。/bin/sh foo.sh 这类调用只会检查 /bin/sh1。Homebrew 装的命令行工具大多没有开发商签名，需要逐个按哈希或路径放行，升级后要重新放行。

三、Linux：四个选项

fapolicyd

fapolicyd 用内核的 fanotify 在文件打开和执行前拦截，要求内核 4.20 或更高。规则从上往下匹配，第一条命中的生效。“可信”的定义来自信任数据库：用 dnf 或 rpm 装包时，RPM 插件自动更新它3。

信任来源写法状态
RPM 数据库RPM 插件自动维护成熟
Debian 数据库trust=debdb初步实现
信任文件fapolicyd.trust，手工加条目成熟

完整性校验可以选三种强度：只比文件大小、用 IMA 提供的哈希、或由 fapolicyd 自己算 SHA-2563。只比大小最快，但同样大小的替换文件能骗过它。

# 先用宽松模式跑：会记 dec=deny，但程序照常运行
sudo /usr/sbin/fapolicyd --permissive --debug-deny

# 把包外的程序加进信任列表
sudo fapolicyd-cli --file add /opt/app/bin/tool
sudo fapolicyd-cli --update

RHEL、Fedora、Rocky 上首选它。Ubuntu 和 Debian 上，先在测试机跑一段宽松模式再决定。

Tetragon

Tetragon 是 Cilium 项目的 eBPF 工具，可以不装 Kubernetes，用软件包或容器单机运行4。它的拦截有两种动作：Override 让被跟踪的函数不执行、直接返回错误；Sigkill 结束进程。官方建议两者一起用，因为只发 Sigkill 不保证拦住触发它的那个操作，例如一次 write() 仍会写完4。

白名单靠选择器 matchBinaries 写，它支持 NotIn 和 NotPrefix5。比如“不在 /usr/bin 和 /opt/app 下的程序，做某个操作时就拦”。它没有现成的“全系统执行白名单”策略，要自己挑内核挂钩点、写 YAML、反复测试。适合已经在用 eBPF、想把白名单和行为检测放在一个工具里的人。

IMA 校验

IMA（Integrity Measurement Architecture）是 Linux 内核自带的功能。打开 appraisal 后，内核在执行文件前检查文件扩展属性里的哈希或签名，不对就拒绝6。它的保证最强，因为检查发生在内核里，用户态程序关不掉。

代价也最高：要生成密钥、给每个可执行文件签名、改内核启动参数。系统每升级一个包都要重新签名。适合镜像固定、很少变动的服务器，不适合日常改动的机器。fapolicyd 可以读 IMA 的哈希，两者能配合用3。

KubeArmor

KubeArmor 主打 Kubernetes，也有在普通主机上运行的模式，支持 allow 策略，按进程、文件、网络限制7。单机使用的文档和案例比前三个少。只在已经用它管容器、想让主机用同一套策略时考虑。

待确认KubeArmor 单机模式能否不依赖 Kubernetes 完整运行 allow 策略，本页没有逐项核对官方文档。

四、上线步骤

先观察，再拦截

  1. 装好后先跑观察模式：Santa 用 Monitor，fapolicyd 用 --permissive。跑 1 到 2 周，覆盖一次系统升级和日常用到的工具。
  2. 把日志里被标为“未知”或 dec=deny 的程序整理出来。有签名的按 Team ID 或包放行，没签名的按哈希或路径放行。
  3. 切到拦截模式。Mac 上如果是自己一个人用，直接选 Standalone，新程序弹窗批准。
  4. 留一条回退路径：知道怎么用本地命令切回观察模式，避免锁死系统。
风险白名单不全就切拦截，最先坏的是系统更新、编译工具链和包管理器的安装脚本。开发机上 brew、cargo、npm 不停产生新程序，维护成本高；固定用途的服务器上效果最好。

白名单之外还要什么

白名单只回答“这个程序能不能启动”。被放行的程序做了什么，它不看。curl … | bash、python -c、被利用的浏览器，都在白名单之内。

系统白名单配一个行为检测配一个状态检查
macOSSantaBlockBlock（盯开机自启项）osquery 或 KnockKnock
LinuxfapolicydFalco 或 Tetragonosquery、AIDE

以上都能单机运行，告警写本地日志或 journald。
