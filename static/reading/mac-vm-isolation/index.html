Mac 上装 Mac 虚拟机：安装、隔离与备份

这页整理 2026 年 11 月 4 日到 5 日一轮问答。问题从“VMware 里能不能装 Mac 虚拟机”开始，落到“物理机被入侵时虚拟机能不能独善其身”和“加密 DMG 够不够当备份”。

问答整理 · 2026-11-05 · 范围：M 系列 Mac、UTM、macOS 27

UTM 可以自动下载安装镜像，不必手动找 IPSW。虚拟机挡的是“虚拟机里出事波及物理机”，挡不住“物理机被入侵后虚拟机被读写”，因为虚拟机的内存和磁盘都在物理机手里。重要文件的备份用 AES-256 加密的 DMG 存到两份离线介质上，比放进虚拟机更合适。M 系列 Mac 可以用 UTM、Parallels Desktop 或 Tart 装 macOS 虚拟机，VMware Fusion 不行。

一、UTM 是什么

1.1 简介

UTM 是一个 Mac 上的虚拟机软件，官网版本免费7。在 macOS 12 或更新的 M 系列 Mac 上，它用 Apple 的虚拟化框架跑 macOS 客户机，新建虚拟机时能自动下载兼容的 macOS 安装镜像4。本页后面的安装、隔离和备份讨论都以它为准。

几个和日常使用有关的限制，来自 UTM 的 macOS 客户机文档4和剪贴板文档19：

  • 共享目录要宿主机和客户机都是 macOS 13 或更新，挂载用终端命令。另一条路是宿主机开 macOS 的网络文件共享。
  • 剪贴板共享要两边都是 macOS 15 或更新，并在客户机里装 UTM 的客户机工具。
  • USB 共享在 macOS 27 之前的客户机上不支持。
  • 窗口之间直接拖放文件不支持。

1.2 UTM 对非技术人员顺不顺手

有人先把虚拟机准备好，非技术人员可以用 UTM。安装和文件共享两步会比较吃力。下表来自它的文档；2026 年 11 月 4 日在 M4 MacBook Pro 上实际装过一台 macOS 27 虚拟机，装得起来。

UTM 各项操作的预期体验
操作预期体验
安装 macOS向导引导安装，能下载兼容的 macOS 安装器。
启动虚拟机在界面里选中虚拟机，点启动。
在里面用软件基本熟悉：窗口里是另一个 Mac 桌面。
两边复制文字需要一个设置和客户机工具。两边都要 macOS 15 或更新。
共享文件夹偏技术。文档里的方法是终端命令或网络共享。

来源：UTM 的安装和共享文档4，虚拟机操作文档10。偶尔测试，推荐它。要频繁传文件、又希望不用人帮忙，先把初始配置做好。

二、安装包与 IPSW

2.1 softwareupdate 下载的安装器在哪

运行下面这条命令后，安装器在 /Applications，不在 ~/Downloads。

softwareupdate --fetch-full-installer --full-installer-version 27.2

找名字是 Install macOS … .app 的应用。要看确切名字，运行：

find /Applications -maxdepth 1 -name 'Install macOS*.app'

这是一个安装器应用。UTM 装 macOS 虚拟机用的是 .ipsw 恢复镜像，两者不是一回事。

2.2 怎么拿到 IPSW

最省事的方法是让 UTM 自己下载：

  1. 在 UTM 里新建虚拟机。
  2. 选 Virtualize，再选 macOS 12+。
  3. IPSW 文件留空，不选。
  4. 继续安装。

UTM 会自动下载最新的兼容 macOS 恢复镜像4。

一定要 27.2 这个版本时：

  1. 打开 IPSW Downloads 的 Mac 页面11。
  2. 选要跑 UTM 的那台 Mac 的型号。
  3. 有 macOS 27.2 就选它。
  4. 点 Download。
  5. 在 UTM 里选中下载好的 .ipsw 文件。

IPSW Downloads 提供的是指向 Apple 服务器的链接，它自己不存安装文件。

2.3 ipsw.me 是什么网站

IPSW.me 是一个独立的 Apple 固件下载链接目录，不是 Apple 的网站。它声明下载直接来自 Apple 的服务器，自己不托管文件副本12。

用它的链接本身不等于下载盗版软件。但一个 Apple 下载链接不等于无限制的使用权。Apple 的软件受版权保护，许可协议管着安装、复制和使用13。装 Mac 虚拟机时：

  • 从 Apple 服务器下载原版 IPSW。
  • 遵守那个 macOS 版本附带的许可协议。
  • 别把“能免费下载”当成“能再分发”或“任何商业用途都行”。

它算一个合理的下载目录。整个网站的法律状态无法认证。UTM 的自动下载仍然是更简单的选择，UTM 也推荐这个方法4。

2.4 公司批量部署要不要分别装

不同型号的 Mac 不自动需要不同的 IPSW。前面让按 Mac 型号选文件的说法过于严格。Apple Silicon Mac 上，一个 macOS 版本通常有一个 Universal IPSW，支持多个 Mac 型号。兼容性仍取决于硬件和 macOS 版本。

公司部署各种情况下要做的事
情况要做什么
员工用的是不同的 M 系列 Mac一个兼容的 IPSW 通常够所有这些 Mac 用。
每个员工要一台独立虚拟机在每台 Mac 上建一台虚拟机。安装器可以复用。
员工升级了物理机的 macOS通常保留现有虚拟机。一般不需要重装。
员工升级虚拟机里的 macOS在那台虚拟机里用“软件更新”。
员工换了物理 Mac把虚拟机迁过去，再检查兼容性。可能不需要重装。

把 IPSW 当作安装源。装好的虚拟机有自己的磁盘和设置，物理机变了不需要重装。公司里先用一套标准虚拟机配置，在用到的各个 Mac 型号上测一遍，再部署。

注意全公司使用必须符合 Apple 的 macOS 许可协议。许可的用途有区别：开发、测试，还是普通办公。

三、虚拟机与物理机的隔离

3.1 装完为什么还要本机密码

要密码不一定表示虚拟机能访问本机文件。看提示出现在哪。

密码提示出现的位置与含义
提示出现在通常表示
虚拟 Mac 的账户设置页给虚拟 Mac 建一个新密码。它可以和物理 Mac 的密码不同。
写着 UTM 的 macOS 权限对话框UTM 请求在物理 Mac 上做某个操作。先读清操作再批准。
Apple 账号登录页这是在接入 Apple 服务。安装阶段通常可以跳过。

虚拟机提供隔离，但 UTM 仍然跑在物理 Mac 上。共享文件夹、剪贴板共享和网络访问都会影响这层隔离。做法：虚拟机里用一个独立密码；共享文件夹和剪贴板共享保持关闭；安装时跳过个人 Apple 账号。当时请对方发提示的截图或原文（隐去个人信息，不发密码），好判断它要的是哪个密码。

3.2 Apple 账号与访问物理机

问题是：虚拟机里要不要用另一个 Apple ID？要不要允许虚拟机访问物理机？当时的设想是把虚拟机当安全设备，把重要文件备份进去。

重要文件的备份，不建议把同一台 Mac 上的虚拟机当主要保护。它仍然依赖那台 Mac。虚拟磁盘是物理 Mac 上的一个文件，磁盘故障或失窃会一起带走两份。有足够权限的恶意软件可以删除或加密这个虚拟磁盘。

Apple 账号：虚拟机只存文件就不登录。需要 iCloud 就用一个独立账号，独立密码加双重认证。这样减少账号重叠，但挡不住被入侵的物理机。登录后虚拟机里就能用 iCloud 服务14。

访问物理机：共享文件夹和剪贴板共享默认关闭。要传文件时，临时只共享一个专用文件夹，不共享主目录或整块磁盘。UTM 支持文件夹共享和网络共享，这些连接都要刻意配置4。

备份这个目标，当时给的方案：

  1. 工作文件留在 Mac 上。
  2. 外置磁盘上放一份加密备份。
  3. 每次备份后断开那块磁盘。
  4. 另一个地点再放一份，带版本历史或防删除保护。
  5. 定期测试文件恢复。

离线加密备份加恢复测试是标准的勒索软件防护措施15。虚拟机更合适的角色是跑不信任的软件，并限制它的访问。重要备份放在这个环境之外。

3.3 物理机被入侵，虚拟机保不住

目标是“物理机被入侵，虚拟机不受影响”。这个目标做不到。虚拟机监控程序（hypervisor）跑在物理 Mac 上，对虚拟机的内存和磁盘有完整的读写权。标准威胁模型里，宿主机被攻破等于它上面每台客户机都被攻破1617。

保护是反方向的。隔离挡的是被攻破的客户机去碰宿主机。就算这个方向，也要靠虚拟机监控程序没有漏洞，而漏洞是存在的。2025 到 2026 年有一例 ESXi 的虚拟机逃逸在野外被利用：攻击者从客户机内部拿到了整个 hypervisor 的控制权18。

所以把虚拟机当作跑高风险工作的沙箱，不当作放重要文件的保险箱。

3.4 仍然值得做的八条规则

这些规则限制的是常见情形的损失：某个软件权限过大、某个会话被盗、恶意软件还没拿到完整 root 权限。

物理机与虚拟机之间的隔离规则
规则原因
虚拟机里用不同的密码一边被截获的密码打不开另一边。
不设共享目录。必须传文件时，共享一个空文件夹，传完就取消共享文件夹是恶意软件双向通行的直路4。
剪贴板共享保持关闭剪贴板会把密码和令牌带到另一边19。
客户机里不登 Apple 账号，或只用一个专给客户机的账号共用账号会把钥匙串、iCloud 云盘和信息同步进客户机。macOS 15 及以后的客户机能登录，并拿到自己的设备身份20。
宿主机不为客户机开 macOS 文件共享和共享目录一样的风险，只是走网络。
宿主机开 FileVault，客户机里也开保护的是物理 Mac 关机或失窃时的虚拟磁盘文件。宿主机开着且已被入侵时没用。
宿主机和客户机都保持更新hypervisor 的漏洞靠这个修。
宿主机的密码不存进客户机，反过来也一样一处失守不变成两处。

四、不常用文件的备份

问题是：不常用的文件，做成带强密码的 DMG，备份到别的介质，够不够？

够，而且比放进虚拟机更合适。

4.1 加密 DMG 的设置

  • 用 AES-256 创建镜像。磁盘工具和 hdiutil 都有这个选项2122。
  • 用长口令。四个以上随机单词，或密码管理器生成的 20 位以上密码。加密本身很强，口令才是弱点。
  • 不把口令存进宿主机的钥匙串。磁盘工具会提议存，拒绝它。
  • 只在信任的 Mac 上创建和挂载镜像。镜像挂载期间，里面的文件对那台 Mac 是明文。
  • 两份副本放两个介质，一份保持断开。例如家里一块外置 SSD，另一个地方再放一块。
  • 口令记在离线的地方。口令丢了文件就丢了，没有重置。
  • 每份副本每年打开一次，确认文件能正常读。

五、其他虚拟化软件情况

这一节回答最早的几个问题：VMware 能不能装，别的软件行不行，macOS 27 支持到什么程度。

5.1 VMware 不行，别的可以

VMware 能不能装 macOS 虚拟机，看电脑是哪种。

VMware 对 macOS 虚拟机的支持
电脑VMware 里装 macOS
Apple Silicon Mac（M 系列）不行。Fusion 不支持 macOS 虚拟机1。
Intel Mac部分旧版 macOS 可以。取决于 Fusion 和 macOS 的版本2。
Windows / Linux PCVMware Workstation 不正式支持 macOS 虚拟机3。

M 系列 Mac 换别的软件就能装。三个选项：

M 系列 Mac 上能装 macOS 虚拟机的软件
软件适合macOS 支持
UTM日常使用和测试在 macOS 12 或更新的 M 系列 Mac 上支持 macOS 客户机4。
Parallels Desktop有向导的安装通过界面下载并安装 macOS 12 或更新版本5。
Tart开发和自动化用命令行运行 macOS 虚拟机6。

做一个独立的 Mac 测试环境，推荐 UTM。官网版本免费7。这三个方案都要求物理机是 M 系列 Mac，在 Windows PC 上做不出 M 系列 Mac 环境。

5.2 macOS 27 的支持情况

macOS 27 可以在 M 系列 Mac 的虚拟机里跑。三个软件的支持程度不同：

  • Tart：当前代码明确支持 macOS 27 客户机，包括自动创建账号8。
  • UTM：文档描述了 macOS 客户机和 macOS 27 的功能，能自动下载兼容的安装器4。
  • Parallels Desktop 27：物理机支持 macOS 27，但官方客户机列表目前到 macOS 26 为止。macOS 27 作为客户机的官方支持未能确认9。

物理机的 macOS 版本也影响安装兼容性。
