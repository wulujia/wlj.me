Mac 入侵日志采集与排查

企业如何集中采集 Mac 日志？哪些事件能帮助发现入侵？本文列出采集工具，以及疑似受入侵 Mac 的检查文件。

范围：企业管理的 Mac，macOS 13 及以上读者：IT 与安全人员

结论

  • macOS 没有直接转发统一日志的设置。企业需在每台 Mac 上安装采集程序，并用 MDM 部署。
  • 统一日志对入侵检测的支持有限。采集应以 Endpoint Security 事件为主。最低要求包括进程执行、持久化、登录和安全防护篡改。
  • 小公司可用 Elastic Defend 或 Jamf Protect 持续采集日志。疑似受入侵的 Mac 可用 Aftermath 单次检查。
  • 排查时先检查启动项、后台项、下载记录、权限数据库和 shell 历史。日志应接近实时发送到服务器。拥有 root 权限的攻击者能删除本机日志。

将 Mac 日志发送到服务器

统一日志的限制

从 macOS 10.12 开始，大部分系统和应用消息写入统一日志（os_log）。统一日志没有发送到远程服务器的设置。

旧的 syslogd 和 /etc/syslog.conf 仍支持转发。例如：*.* @logserver:514。它们只能收到仍使用旧 syslog() API 的程序消息。这些消息只占少量日志，不能依赖这种方式。

三种采集方式

企业 Mac 日志的集中采集方式
方式工作方式适用情况
商业采集程序用 MDM 安装 EDR 或日志采集程序。程序使用 Apple 的 Endpoint Security 框架，将事件发送到产品云端或企业 SIEM。需要现成的检测规则和告警。大部分企业使用此方式。
自行搭建launchd 守护进程运行 log stream --style ndjson --predicate '<filter>' 或 eslogger。Mac 上的 Fluent Bit 或 Vector 读取输出，通过 TLS 转发到 Loki、Elasticsearch、Graylog 或 syslog。需要应用或系统日志排查故障。企业有人编写过滤规则和告警。
按需采集运行 log collect 或 sysdiagnose，然后上传文件。单次故障排查。无法持续采集。

自行搭建时，请用 --predicate 过滤。完整日志流的数据量很大。

MDM 部署工作

  • 静默安装采集程序的软件包。
  • 下发 PPPC 配置描述文件，授予采集程序完全磁盘访问权限。
  • 通过配置描述文件批准程序的系统扩展。否则，每位用户都会收到批准提示。
  • 通过 launchd 任务保持采集程序运行。产品支持防篡改时，请启用该功能。

隐私、法律与数据量

  • 隐私：统一日志将许多值显示为 <private>。日志配置描述文件可显示这些值。采集范围也会包含更多个人数据。
  • 法律：新加坡适用 PDPA10。请告知员工采集内容和目的，并写入 IT 政策。其他员工所在国家也需检查当地要求。
  • 数据量：请在 Mac 上过滤日志。不要发送全部内容。过滤可减少带宽、电池消耗和服务器费用。

需要采集的事件

Mac 可能受入侵时，本机日志的可信度有限。采集应记录运行的程序、重启后保留的项目、登录者和关闭的防护。请将事件接近实时发送到服务器。

主要来源：Endpoint Security

  • 统一日志无法可靠记录进程启动、文件变更和持久化。
  • 请使用基于 Apple Endpoint Security 框架的采集程序1。选项包括 EDR、Elastic、Wazuh，或启用 Endpoint Security 的 osquery。
  • 自行搭建时，macOS 13 及以上自带 eslogger。它将 Endpoint Security 事件输出为 JSON。它需要 root 和完全磁盘访问权限。
  • OpenBSM 审计（praudit、/etc/security/audit_control）已弃用。请勿以它为基础搭建采集系统。

采集优先级

P0 是最低采集要求。原讨论认为，P0 可帮助发现大部分实际 Mac 入侵。例子包括信息窃取程序、假安装程序和 SSH 密钥盗用。本文未提供该覆盖率的实测数据。

每日状态快照

快照能补充实时事件遗漏的变更。osquery5 适合此任务。请每天记录一次：

  • 已安装应用及其签名。
  • 浏览器扩展。
  • 配置描述文件。
  • SIP、FileVault、Gatekeeper 和防火墙状态。
  • admin 组成员。

保护日志

  • 请每隔几分钟发送一次心跳。Mac 停止发送时，请触发告警。日志中断可能说明攻击者停止了采集程序。
  • 请使用 TLS。请为每台 Mac 分配独立证书来验证身份。
  • 请将日志保存到服务器。Mac 只能写入，不能读取或删除。
  • 所有 Mac 和服务器应使用同一准确时间源。日志应使用 JSON 等结构化格式3。否则，难以将不同 Mac 的事件合并到同一时间线。
  • 建议至少保留 90 天。许多事件在数周后才发现。

无需完整采集的内容

  • 完整统一日志流的数据量很大。大部分内容对发现入侵帮助有限。
  • 请勿采集所有路径的文件事件。请限定敏感目录，避免数据量过大。

优先级的依据

参考指南的共同重点

macOS 没有官方的完整采集优先级表。本文参考 MITRE ATT&CK 的 macOS 矩阵2，以及 2024 年的联合事件日志指南3。后者由 ASD 的 ACSC、CISA、NSA 等机构发布，合作机构包括新加坡 CSA。原讨论据此将进程执行、持久化和身份验证列为优先采集内容。P0 可作为开始部署的参考。

请按企业实际威胁调整优先级。开发人员较多的公司，应更关注 SSH 密钥和云服务凭据。

针对当前威胁的两项调整

  • DNS 列为 P1。企业 DNS 或网络网关已记录查询时，新增成本很低。多数恶意软件需要连接其服务器，DNS 能提供线索。
  • 信息窃取行为列为 P0。原讨论将 AMOS、Poseidon 等信息窃取程序视为当前常见 Mac 威胁。它们用 osascript 伪造密码提示，然后读取钥匙串和浏览器文件。“最常见”的判断缺少本文可核对的单一报告，详见方法与来源。

疑似受入侵 Mac 的检查文件

检查前的准备

警告拥有 root 权限的攻击者能修改下列文件。Mac 确认受入侵时，服务器日志通常比本机文件更可信。
  • 请先采集，再分析。采集前请勿重启或清理 Mac。否则，运行进程和网络连接信息会丢失。
  • 许多文件需要 root 和完全磁盘访问权限。

第二层：发现线索后继续检查

  • 配置描述文件：sudo profiles show -all。恶意软件可安装带代理或根证书的配置描述文件。
  • 账户与管理员：dscl . -list /Users、dscl . -read /Groups/admin。
  • Shell 启动文件：/etc/zshrc、~/.zshrc、~/.zprofile。它们可在每次终端启动时执行代码。
  • Cron：/usr/lib/cron/tabs/。
  • 浏览器扩展：Chrome、Edge 和 Safari 的用户配置目录。
  • 文件系统变更记录：/.fseventsd/。它能帮助整理时间线。
  • 运行状态：ps aux、lsof -i、systemextensionsctl list。请在重启前采集。

向用户展示排查结果

请将原始日志整理成一份报告。报告按以下顺序排列：

  1. 时间线：按时间排列下载、安装、新增持久化项目和新增权限。
  2. 持久化项目：列出每项的签名者、Team ID 和路径。请标记未签名项目及未知开发者项目。
  3. 权限：列出拥有完全磁盘访问、屏幕录制或辅助功能权限的应用。
  4. 发现：将每项标为正常、可疑或恶意。请用一句普通话说明依据。
